# Clean data dictionary

This document defines the identity, units, geometry, layout, and provenance of
data accepted by `clean_v1`.
Examples in the committed templates are illustrative and are not accepted until
every placeholder is replaced and every hash is verified.

## Identity hierarchy

The immutable per-observation identity is:

```text
(run_id, dataset, subject_id, slice_id, count_level, realization_id)
```

- `dataset` is exactly `brainweb` or `hecktor`.
- `subject_id` denotes a BrainWeb source model or one HECKTOR patient.
- `slice_id` identifies one independently simulated 2-D axial ring position.
- `count_level` is the expected total detected-count proxy, one of 100k, 200k,
  500k, or 1M.
- `realization_id` is 0, 1, or 2 and selects an independent deterministic random
  stream.

The Qwen box identity deliberately omits `realization_id`:

```text
(run_id, dataset, subject_id, slice_id, count_level)
```

It is generated from the r=0 MLEM-10 image and shared by r=0/1/2.

## Dataset units and source interpretation

| Dataset | Source | Required unit declaration | Clean spatial transform | Important limitation |
|---|---|---|---|---|
| BrainWeb | Noise-free simulation activity NIfTI | Exact simulation activity unit from source definition | Exact 2x2 mean-pool of the complete square to 128x128 | Different simulations of one source model must not cross splits |
| HECKTOR | Reconstructed PET slice exported directly from clinical DICOM | Unit verified from the DICOM export pipeline | Bilinear resize of the complete 144x144 square to 128x128 | Radon data are pseudo-sinograms from reconstructed clinical PET, not scanner raw events |

`normalization.scale_constants.<dataset>` must have the same unit as the
ingested activity.
The committed HECKTOR samples have SUV maxima around 4.5--15.2, so a value near
30000 is not dimensionally valid for those arrays.
The provisional `C_BW=6` and `C_HE=35` diagnostics are train/validation coverage
candidates, not accepted physical constants.

## Subject inventory

File: `inputs/clean_v1/subject_inventory.csv`, copied from
`inputs/subject_inventory.template.csv`.

| Field | Definition |
|---|---|
| `dataset` | `brainweb` or `hecktor` |
| `subject_id` | Stable source-model or patient identifier |
| `stratum` | Predeclared simulation family, scanner, or site used for balancing; never a post-hoc performance group |
| `previous_exposure_status` | `development_allowed` or `never_used_for_training_validation_tuning_or_reporting` |

Only never-exposed subjects can enter the new locked test set.

## Subject split

File: `inputs/clean_v1/subject_split.csv`, generated by `sam-kem create-split`.

| Field | Definition |
|---|---|
| `dataset`, `subject_id` | Primary key |
| `split` | `train`, `validation`, or `test_locked` |
| `split_id` | Must match `data.split_id` in the contract |
| `split_locked_utc` | UTC creation timestamp |
| `source_inventory_sha256` | SHA of the exact inventory used |
| `split_script_sha256` | SHA of the split implementation |
| `previous_exposure_status` | Copied exposure declaration; locked-test rows must be never-exposed |

The whole CSV is SHA-pinned as `data.split_sha256`.
Expected subject counts are BrainWeb 14/3/3 and HECKTOR 156/34/34 for
train/validation/test.

## Source activity manifest

File: `inputs/clean_v1/source_activity_manifest.csv`, copied from
`inputs/source_activity_manifest.template.csv`.

| Field group | Required content |
|---|---|
| Identity | `dataset`, `subject_id`, `slice_id`, `split` |
| Source | `source_path`, full-file `source_sha256`, `source_kind`, and optional archive `source_key` |
| Selector | Subject index, slice axis/index, and channel index needed to reproduce the selected 2-D array |
| Quantitation | Native `activity_unit` |
| Transform | Exact named `spatial_transform` |
| Optional spatial metadata | Source y/x spacing in mm when retained from DICOM; not required by the pixel-domain operator |

Absolute source paths are allowed locally but may need de-identification before
commit.
The SHA and selectors, not the workstation path, establish reproducibility.

## Normalization activity manifest

File: `inputs/clean_v1/normalization_activity_manifest.csv`, copied from
`inputs/normalization_activity_manifest.template.csv`.

Each unique ingested train/validation `raw_activity.npy` slice appears once with
its canonical array SHA and native unit.
Test rows are prohibited.
This manifest supports the scale sensitivity study; it does not itself select a
normalization.

## Canonical array layout

```text
arrays/clean_v1/<dataset>/<subject>/<slice>/
  raw_activity.npy
  raw_activity.json
  target.npy
  noise_free_projection.npy
  noise_free_projection.json
  anatomy.npy                         # optional, named baseline input only
  c<count>/r<realization>/
    sinogram.npy
    sinogram.json
    mlem10.npy
    mlem10.json
    sam_prior.npy
    sam_prior.json
    sam_prior_centroid.npy            # ablation only
    sam_prior_centroid.json
    sam_prior_released.npy            # ablation only
    sam_prior_released.json
```

Expected shapes are 128x128 for activity/target/prior arrays and 180x182 for
projections/sinograms.
The first sinogram axis indexes angles.
No external `evaluation_mask.npy` is allowed; metrics and KEM neighborhoods use
positive sensitivity of the same PET operator.

## Meaning of the core arrays

| Array | Definition |
|---|---|
| `raw_activity.npy` | Ingested source slice in its declared native quantitative unit |
| `target.npy` | `(raw_activity - offset) / C`; fixed-C primary uses zero offset and no clipping |
| `noise_free_projection.npy` | `A target` from the locked 180-angle clean operator |
| `sinogram.npy` | Independent draw `Poisson(s A target)`, where `s=N/sum(A target)` |
| `mlem10.npy` | Exactly ten MLEM iterations using that sinogram, gain, operator, and fixed initialization; used as the prompt/model input |
| `anatomy.npy` | MR for BrainWeb or CT for HECKTOR, used only by applicable named comparison baselines |
| `sam_prior*.npy` | Continuous MedSAM2 decoder output; display/fusion clipping and kernel-feature min-max are distinct declared operations |

The count level is an expected detected-count proxy.
It is not a calibrated injected dose.
Poisson noise models counting statistics, not detector thermal noise.

## Sidecar rules

Each generated NumPy artifact has a JSON sidecar that binds the array SHA to its
identity and producing inputs.
Depending on artifact type it also records source/ingestion metadata SHA,
operator ID and implementation SHA, normalization identity, projection scale,
RNG seed, realized counts, MLEM iteration count, box record, or decoder SHA.

The case-manifest builder reopens and verifies all required arrays and sidecars.
A file existing at the expected path is not sufficient.

## Case manifest

The case manifest has one row per six-field observation identity and includes:

- split ID/SHA, seed, normalization ID/offset/clipping/C, and operator ID;
- relative paths to target, projection, sinogram, MLEM-10, anatomy, and priors;
- paths to projection/simulation/MLEM/prior sidecars;
- realized total counts and projection scale;
- anatomy SHA, when an anatomical baseline is applicable.

Anatomy is not an input to the proposed method and never defines the evaluation
support.
The verified case manifest is the only case source consumed by experiment
protocols.
